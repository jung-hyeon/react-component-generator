# pr: 변경사항 분석 후 PR 생성

현재 브랜치를 기준 브랜치(기본 `main`)와 비교해 PR 제목과 본문을 작성하고, `gh`로 PR을 생성한다.
별도 컨텍스트(fork)에서 실행되므로 결과는 마지막에 요약해서 보고한다.

## 절차

### 1. 사전 확인

다음을 실행한다.

- `git branch --show-current` — 현재 브랜치
- `git status --short` — 커밋되지 않은 변경 확인
- `gh auth status` — GitHub 로그인 확인

아래 경우는 PR을 만들지 않고 이유만 보고한 뒤 종료한다.

- 현재 브랜치가 기준 브랜치(`main`)와 같다. (PR은 작업 브랜치에서 만든다. 브랜치를 새로 만들거나 옮기지 않는다.)
- 기준 브랜치 대비 커밋이 없다.
- `gh`가 로그인되어 있지 않다.

커밋되지 않은 변경이 있으면 PR에 포함되지 않는다는 점을 보고에 적는다. 직접 커밋하지 않는다.

### 2. 변경사항 분석

- `git log main..HEAD --oneline` — PR에 포함될 커밋
- `git diff main...HEAD --stat` — 변경 파일 규모
- `git diff main...HEAD` — 실제 변경 내용. 큰 diff는 핵심 파일 위주로 읽는다.

커밋 메시지가 아니라 **실제 diff**를 근거로 작성한다.

### 3. 본문 작성

`references/pr-template.md`를 읽고 그 양식의 섹션 순서와 제목을 그대로 따른다.

- 제목: `<type>: <한국어 요약>` 형식, 70자 이내. 커밋이 하나면 그 메시지를 쓰고, 여럿이면 전체를 아우르는 요약을 쓴다. type은 feat, fix, refactor, chore 중 하나.
- 본문: "무엇을 했는지"보다 "왜 필요한지"를 먼저 쓴다. 확인하지 않은 내용(실행하지 않은 테스트 등)은 적지 않는다.
- 테스트 섹션에는 이번에 실제로 실행한 명령과 결과만 적는다. 실행하지 않았다면 "미실행"이라고 쓴다.
- 시스템 안내에 PR attribution 줄이 주어져 있으면 본문 맨 끝에 그대로 덧붙인다. 없으면 임의로 추가하지 않는다.

### 4. push와 PR 생성

- 원격에 브랜치가 없으면 `git push -u origin <현재 브랜치>`로 올린다.
- 본문은 heredoc으로 전달해 줄바꿈이 깨지지 않게 한다.

```bash
gh pr create --base main --title "<제목>" --body "$(cat <<'BODY'
<본문>
BODY
)"
```

- 이미 같은 브랜치의 열린 PR이 있으면(`gh pr view`로 확인) 새로 만들지 않고 그 URL을 보고한다.

### 5. 결과 보고

1. 생성된 PR URL
2. PR 제목과 포함된 커밋 목록
3. 포함되지 않은 변경(커밋되지 않은 파일)이나 미실행 테스트 등 주의할 점

## 규칙

- `--force` push, 기준 브랜치로의 직접 push, PR 자동 머지는 하지 않는다.
- `.env`, 키, 토큰 등 자격 증명이 diff에 보이면 PR을 만들지 않고 사용자에게 알린다.
- PR 본문은 한국어로 작성한다. 코드 식별자와 명령어는 원문 그대로 둔다.
